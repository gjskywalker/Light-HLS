# 为什么在真实 HLS 后端研究 Agent 开发的调度算法

## 要解决的问题

给定程序、目标器件、时钟和访存接口，调度器需要决定操作何时执行，并生成能实现这些决定的电路。我们关注的是：编码 Agent 能否利用少量开发程序暴露的冲突、转发条件和 RTL 结果，提出一条可复用的调度规则，使未见过的程序也获得正确、更快的实现？Light-HLS 提供可修改的调度决策点、下游编译器和可独立运行的 RTL，允许研究者跟踪一条规则从生成到生效的全过程。

## 已有实验提供的动机

**在理想化图上求得最优解，仍留下了真实编译器中的问题。** 在 HeuriGym 的七张预留图上，两份 Codex 调度器都达到了作者报告的 ILP 周期，较手写关键路径列表调度的完成周期几何平均缩短 2.79%，四张图各省一拍，代价是求解时间更长。这个结果支持把图作为低成本的算法试验场。图能表达哪些约束取决于建模时保留了哪些信息；这些图没有检验同一个调度能否映射为功能正确的 RTL。[第一轮报告](../../experiments/operator_scheduling/round1_20261120/README.md) · [HeuriGym](https://arxiv.org/abs/2506.07972)

**有些硬件约束随调度决策本身改变。** 在 Light-HLS 的 `lookup_xor` 中，关键路径优先把索引读取提前一拍，随后端口被另一个请求占用。导出图上的依赖和端口检查均通过，预测仍为 5 周期；后端重算时发现索引值无法在原定边沿直接转发，必须捕获该值，因而拒绝原先请求的起始周期。这个反例给出了可检验的机制：固定操作延时会遗漏依赖于访存顺序的捕获或转发代价。[编译器回放反例](../../experiments/operator_scheduling/flow_pilot_20261124.md)

**需要检验策略是否迁移，以及选中一次好结果需要多少搜索。** 抽象图实验中，10 次独立请求使用相同提示，复核后 7 个候选在 12 张验证图上全部达到参考值，另 3 个仅在同一张图上多用一拍。首轮反馈组入选的也是尚未收到反馈的候选。真实后端试验中，固定诊断与主动诊断各有 1/3 条轨迹把预留设计 `hamming_distance` 从 8 周期缩至 7 周期；手写关键路径规则在该例能达到 6 周期。主动诊断还出现过修复回放失败并保住一个设计的收益、同时失去另一设计收益的轨迹。应同时公布所有重复、失败和强基线，区分偶尔找到解与稳定产生收益。[候选复核](../../experiments/operator_scheduling/round1_20261120/README.md) · [三组诊断对照](../../experiments/operator_scheduling/diagnostic_flow_20261125.md)

## 论文应当检验什么

1. **后端证据的价值。** 在同一编译器、绑定和接口条件下，比较只看周期、固定诊断和主动查询；跟踪修改了哪一步分配、消除了哪个冲突、最终 RTL 改变了多少周期。KDA 的候选谱系、由 profiler 提出可证伪的假设、独立验收，可用于组织这个实验。[KDA 工作流](https://github.com/NVlabs/kda/blob/main/docs/agent-flow.md)
2. **同一条规则的适用边界。** 将相关程序家族整组留出，事先固定选择规则和回退条件。与原生调度、关键路径优先并在失败时回退、以及适用时的精确下界对照。分别记录正确覆盖、逐例快／平／慢、最差退化、搜索开销和不同运行的波动。
3. **跨工具竞争力。** 使用作者的程序、输入、计时边界、器件、时钟及可核实的资源配置，分别对照同类指标。单事务完成周期、流水 II、动态吞吐、面积和布局布线后时间回答不同问题。跨工具的差异也含前端、存储架构、绑定等因素；仅在同一后端替换调度决策的实验可较好地隔离调度器贡献。[论文与材料清单](../../benchmarks/hls_scheduling_2024_2026/README.md)

当前最有依据的论文切入点，是用编译器反例解释图级成绩与端到端成绩为何分离，再检验后端反馈能否让 Agent 学到跨程序仍有效的调度策略。上述观察支持这个研究问题；能否赢过强基线取决于冻结后的实测结果。

## 11 月 25 日的端到端证据

修复正确性后，27 个完整程序都能参加同后端对照。把 Agent 的选择范围从就绪操作排序扩到多个循环流水，19 个预留程序相对原生少用 11.26% 周期；同预算手写控制少用 13.27%。这给出了比“模型会不会写调度器”更具体的问题：模型在哪一类程序上能做出手写策略缺少的选择？例如，Agent 在 ADI 选中了能缩短周期的循环，而在 FDTD-2D 的有限探测预算内错过了人工找到的候选。[逐程序对照](../../experiments/operator_scheduling/paper_sweep_20261125.md)

调度质量还取决于能否按目标频率运行。在首次冻结策略的 Cholesky 物理对照中，Light-HLS 比 Bambu 少用 35,705 个周期；同一器件布局布线后，它未达到 100 MHz，估算执行时间反而长 13.4%。一个能让 Agent 学到硬件规律的评测平台，需要同时提供功能反例、操作与访存诊断，以及最终网表的时序证据。[同器件预留实验](../../experiments/operator_scheduling/paper_physical_holdout_20261125.md)
