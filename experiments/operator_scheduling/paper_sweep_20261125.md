# 从调度图到真实 RTL：论文 benchmark 上的 Agent 实验

2026 年 11 月 25 日。研究问题是，在给定编译器、目标器件和搜索预算时，Agent 从少量开发程序学到的调度规则，能否让其他完整程序的正确 RTL 跑得更快。比较分为同一编译器内替换规则、同源程序跨工具对照、作者图模型内求解三个层次。它们回答的问题不同。[研究动机](../../docs/research/03_hls_scheduling_motivation.md) · [14 篇论文及基线评估](paper_baselines_20261125.md)

**最终结果。** 修复编译器后，完整 PolyBench 的原生、人工和 Agent 均通过 27/27 项四态 RTL 校验。在 19 个预留程序上，Agent 多循环流程相对原生少用 11.26% 周期，同预算人工流程少用 13.27%。按作者归档的绝对周期，Agent 在 27 项中有 26 项快于 Vericert hyperblock，8 项快于作者逐程序最强配置。独立布局布线还发现周期领先、整程序估算时间落后的例子。当前证据支持后端反馈和循环流水的价值，尚不足以证明 Agent 比强人工策略更能发现通用调度规则。[完整修复版逐项结果](paper_repaired_results_20261125.json) · [预留物理验证](paper_physical_holdout_20261125.md)

用最终多循环部署的实际 RTL 再核对同样 7 个程序，5/7 满足 100 MHz，按布局布线后的估算执行时间有 1/7 快于 Bambu，即开发集 GEMM，四个抽取的预留程序均较慢。[最终 7 个网表的时序、面积与时间](paper_physical_final_20261125.md)

## 完整程序的实验配置

- **输入和划分。** 27 项保留作者的尺寸、初始化、运算和校验，使用 `SYNTHESIS` 宏并将顶层重命名为 `benchmark_main`。通过 Clang 提取原生 C 返回值，对整段 start/done 仿真计时。开发集是 GEMM、BiCG、Jacobi-1D、LUDCMP、Nussinov、MVT、GESUMMV、SYRK，包括了所有用作前置硬件试验的设计。其余 19 项预留；划分按程序，同一家族可能跨集合。
- **调度和器件。** `xc7z020clg484-1`，10 ns，按该器件及时钟重新表征操作库。所有同后端对照使用同一冻结编译器。每次普通块比较保留相同依赖、转发、端口和状态分配；源循环请求 II=1，并以编译器实际达到的 II 为准。
- **选择和搜索开销。** `gpt-6.1-sol`、低推理强度、临时会话。普通块三次请求，只比较开发集；循环排序两次请求，每个策略每程序最多试三个候选循环，共享缓存的相同编译只需执行一次。测试时冻结权重，无逐测试程序的模型请求。三次和两次是顺序迭代的候选数，估计随机种子方差仍需要独立重复。图实验的模型预算另计。
- **验收和统计。** 原生 C 的固定输入返回值与 Icarus 四态 RTL 在 `ap_done` 时必须一致。单次功能仿真墙钟限时 240 秒。仅两个实现都通过时比较周期，胜／平／负和覆盖分开列出。每个程序等权，对“策略周期／对照周期”取几何平均；表中降低百分比为一减该比值。循环静态成本用于部署前选择，末端 RTL 检查失败会记入失败。物理比较另列。

## 怎样修改了调度流程

1. **把 Agent 的决策移到真实后端能执行的位置。** 旧回放接口要求 Agent 给出绝对起始周期，`lookup_xor` 的内存读转发反例说明，这个周期可能在重新分配端口后失效。新接口让 Agent 给出就绪操作优先级，由原生后端确定合法起始周期。普通块四个特征依次是剩余关键路径、访存链长度、扇出和操作延时，冻结权重为 `[4,8,1,-2]`。手写关键路径使用 `[1,0,0,0]`。根据编译器逐块状态数部署；有块缩短而其他块变长时，只重编选中块，并复核新状态数。[普通块实验](paper_order_flow.py)
2. **让 Agent 选择值得流水化的循环。** 在开发程序上，普通块优先级常常改变不了整程序周期。扩展允许 Agent 对源码循环排序，五个特征依次是嵌套深度、数组引用、乘法、条件和复合赋值，冻结权重为 `[4,-5,2,0,-1]`。在三个探测中选编译器预测节省最多且迭代次数可证明的简单循环；无正收益时使用普通块路径。手写对照按最内层优先、同深度按源码顺序获取相同探测预算。[循环实验](paper_loop_flow.py) · [冻结后回放](paper_frozen_replay.py)
3. **把合法性问题反馈给编译器。** 修复整数 min/max 降低、1 位符号扩展及部分地址分析问题。对三角循环 `j <= i`，原编译器可将最大迭代数误作每次调用的精确次数；现要求 LLVM ScalarEvolution 证明固定次数，对展开后的外层也复核。新增三角循环回归；冻结版通过项目的 27/27 组本地回归。此前用错误次数获得的周期不进入主结果。[三角循环测试](../../Light_HLS/Tests/PipelineBackend/triangular_trip.cpp) · [编译失败与仿真反例](paper_exception_checks_20261125.md)
4. **考察多个合法循环的组合。** 在固定的三个循环探测中，如至少两个有正收益，再做最多一次联合编译，验证每个循环确实实现、迭代次数相同、II 没有恶化，随后对组合 RTL 做完整校验。手写与 Agent 使用同样的额外预算。这项是在见过本批初步结果后的探索，不能作为新的独立留出验证。[联合流水入口](paper_joint_pipelines.py)

## 正确性修复后的全部 27 项

首次冻结实验有三个原生失败。沿 LLVM IR、RTL 内存与 FSM 追踪后发现，跨基本块提升的读可以越过同地址写，另有把字节偏移当成 RAM 元素下标的问题。限制缺少依赖证明的读提升恢复了 Nussinov、LU；在证明元素对齐时恢复字节 GEP 对应的元素索引又恢复了 ADI。逐字核对了这三例的整个结果数组，分别为 3,600、1,600 和 400 项。两次修改都是在见过失败案例后实施的编译器修复。正式复跑沿用此前冻结的策略、输入和预算，没有把这三项用于重新训练。[错误定位、修复及完整数组差分](paper_exception_checks_20261125.md)

| Agent 多循环对原生 | 16／11／0 | 11／8／0 | **−11.26%** |
| 手写多循环对原生 | 15／12／0 | 10／9／0 | **−13.27%** |

在 27 项上，原生已有 5 项快于作者逐例最强配置；调度流程额外使 GEMM、2MM 和 Durbin 越过该参照。修复版的 ADI 是 Agent 胜过同预算人工的一项，单循环从 271,321 降到 259,441 周期。在另外三个预留程序上，人工多循环策略更快。对所有 27 项，Agent 多循环相对原生少用 10.32% 周期，相对手写多用 1.62%。全程序可执行使这类按程序归因成为可能。这里比较 RTL 周期，器件时序需另行验证。[完整结果、编译器 SHA、循环探测及胜负统计](paper_repaired_results_20261125.json)

对最终部署的两种多循环策略，还在四态仿真完成拍读出了 27 个程序的全部最终输出数组。每种策略共 31 个数组、22,502 个 32 位元素，全部与对应 C 逐项一致，未出现未知值。两种策略共用部分网表，合计 31 份不同 RTL。官方输入下有 11 个程序的完整结果数组全零，其中包括周期领先的 GEMM、2MM、3MM、DOITGEN；即使逐元素通过，单组全零输出对计算逻辑的区分力仍有限。[全部数组、预期非零数及逐项比较](paper_final_arrays_20261125.json)

对这四个全零的周期胜例，又在实际部署网表上施加了非零压力输入。保留原初始化和硬件，在进入计算前替换输入 RAM，每例使用三个固定种子；12 次四态仿真共 6,588 个输出元素，全部与启用 UBSan 的原生 C 一致。每次仿真得到 76 至 346 个不同的输出值。这里验证的是同一电路的实际计算，压力用输入单列，不增加论文性能对照的样本数。[数组校验、注入边界和压力实验](paper_final_arrays_20261125.md)

对全部 24 项，Agent 单循环和多循环较原生分别少 7.09% 和 11.37% 周期。对作者给出的 Vericert hyperblock 周期，两版均 23 胜、1 负。对归档五种配置中各程序的最低周期，两版均 **7 胜、17 负**，其中预留集 5 胜、12 负；单循环和多循环在预留集分别比该最强参照多用 29.87% 和 23.04% 的周期。主实验单个最大差距在 `trisolv`，34,780 对 7,802 周期；两条策略都探测了其两个计算循环，内层被编译器以无法证明固定迭代次数拒绝。这个例子需要扩展可实现的调度，单纯调整循环排名无法改变结果。

同预算手写控制揭示了两个不同的失分原因。`covariance` 中两个循环的单次预测收益都为 60，但整程序实测分别为 85,814 和 108,494 周期；循环调用频率能区分这个差距。`fdtd_2d` 中，手写策略的三个探测覆盖收益最高的第 8 个循环，Agent 把一次机会放在收益为负的第 2 个循环，错过了第 8 个。相反，同时流水化多个有收益的循环可以改善同一程序：预留集 `3mm` 从原生 98,532 降到单循环 81,108，再降到多循环 59,476，手写与 Agent 在该例打平。[循环选择、逐项周期及对应的人工对照](paper_sweep_20261125.json)

## 用执行热点改进 Agent 的探测选择

在修复前的 24 个正确程序上，额外用 Icarus 逐拍计数，在程序返回值和原生周期完全相同时，把 FSM 访问频率映射到 113 个源码循环。人工控制按动态热点挑循环，再用单次预测节省乘实际调用次数选择部署。第一轮把相同信息给一次新的临时 Codex 会话，它仅看到 8 个开发程序。两边在 7 个可用开发程序上打平；在 17 个预留程序上，Agent 对原生平均少用 7.93% 周期，人工少用 8.62%。Agent 在 Heat-3D 与 Jacobi-2D 错过热内循环，对人工 0 胜、15 平、2 负。[热点采集、费用和逐项结果](paper_profile_20261125.md)

第二轮给 Codex 开发集反馈，固定保留人工排名第一的候选，只允许它调整余下两个探测名额，并事先规定候选必须在开发集严格胜出才能替换人工策略。原始候选改变了 15 个程序的探测集合，功能均通过；7 个开发程序的周期仍全部打平。冻结时因此选择人工，预留 17 项全部与人工相同。单独公布未获选模型候选：它保住了 Heat-3D 和 Jacobi-2D，在 Gemver 用了 44,792 拍、人工用了 43,232 拍，预留对人工 0 胜、16 平、1 负。这个部署规则防止了开发阶段无新增收益的模型候选取代强基线。两轮均在研究者已经观察过首次预留结果后设计，不算新的盲测。[第二轮候选与部署结果](paper_profile_residual_results_20261125.json)

将同一套热点规则原封不动地迁移至修复后编译器，重新采集了 27 个程序的全部 128 个循环头，两边各使用 79 次逻辑探测。19 个预留程序上，原始模型热点候选较原生少用 7.34% 周期，冻结的人工部署少用 7.97%；原始候选相对人工 0 胜、17 平、2 负。两种热点排序现在都能在 ADI 上找到 259,441 周期的循环。前表里静态 Agent 在 ADI 胜过静态手写排序，加入热点后的手写控制也能复现这一收益。[修复版热点迁移、数据划分与校验](paper_profile_portability_results_20261125.json)

## 外部迁移和硬件表现

普通块策略冻结后，另在 54 项已通过功能验证的非 Vericert 配置上跑四组输入。Agent 和手写关键路径均 54/54 通过，并逐项打平。相对原生，两者各 1 胜、53 平、0 负，几何平均周期少 0.51%。唯一改善的 `gaussian` 在 `for_body8` 改变分配后从 12,022 降到 9,115 周期，少 24.18%。在 Out with LSQs 的九个合格原始驱动上，本工具周期数三项较论文 Ours 小、六项较大；其中两项在原生编译时已领先。两边的协议和器件仍有差异。[四组输入及逐项结果](source_benchmark_sweep_20261125.md)

最终修复版再次扫描了全部 115 条配置。U250 下通过功能验证的外部配置增至 56 条，包括先前失败的两条 CRUSH `symm_float`；两条策略在 56 项的四组输入上全部通过。两者的周期仍逐项相同，较原生 1 胜、55 平、0 负，几何平均减少 0.49%。按配置 ID 取并集，56 个外部配置加上 Zynq 上通过的 27 个 Vericert 配置，共有 **83/115 条源码配置**在至少一种受测 Light-HLS 配置上通过 C/RTL，不能按独立算法计数或混合计算加速比。[修复版源码输入与结果](source_repaired_results_20261125.json) · [Agent](source_repaired_agent_20261125.json) · [手写](source_repaired_manual_20261125.json)

对预先指定的三个开发程序，使用 Vivado 2025.2 在相同 Zynq 器件和 10 ns 约束对原生、单循环部署、作者 Vericert hyperblock RTL、作者 Bambu 默认优化 RTL 完成 12 次 OOC 布局布线。所有实现的 setup 和 hold 均满足约束。下表是仿真周期乘以各自布局布线后估算的时钟周期，单位 µs；板上实时时间未测量。[物理报告、资源和计时边界](paper_physical_20261125.md)

| 完整程序 | Light-HLS 原生 | Light-HLS 单循环部署 | Vericert hyperblock | Bambu 默认 |
| --- | ---: | ---: | ---: | ---: |
| GEMM | 784.00 | **637.12** | 2,251.31 | 658.65 |
| BiCG | 341.07 | 336.69 | 629.48 | **129.62** |
| Jacobi-1D | 40.31 | 36.12 | 138.99 | **18.62** |

GEMM 比 Bambu 少 12.04% 固定频率周期，按各自实现的时序估算时间少 3.27%；BiCG 和 Jacobi-1D 分别需要 Bambu 的 2.60 倍和 1.94 倍估算时间。这三个程序上，预设手写规则与 Agent 各自选择了相同的循环，生成的 RTL 逐字节一致。这些硬件数据支持循环流水的收益，无法据此将收益归因于模型选出的权重。作者 hyperblock 的三份归档 RTL 重跑周期与其原始 CSV 略有出入；物理表采用本次实测，完整程序周期对照单列作者原始五列。

随后在原冻结实验的 17 个合格预留程序中，按预先写定的 ID 哈希排序取 4 项，实测同一器件和 Vivado 下的 Bambu 与 Light-HLS。FDTD-2D、SYR2K、TRMM、Cholesky 的单循环 Light-HLS 估算时间分别为 1,910.11、742.34、323.35、3,402.84 µs；Bambu 分别为 915.30、549.54、231.38、3,000.53 µs。Light-HLS 四项均较慢，且只有 SYR2K 和 TRMM 满足 100 MHz。Cholesky 的 Light-HLS 比 Bambu 少用 35,705 个周期，但因最坏建立裕量为 −2.072 ns，布局布线后的估算执行时间反而长 13.4%。FDTD-2D 的单循环较原生估算时间缩短 18.43%，仍未满足 100 MHz。以上硬件结论针对实际布线的 RTL；修复版、多循环或热点版本需要自己的网表验证。[预留物理报告与逐个资源](paper_physical_holdout_20261125.md)

增加了固定频率部署检查。对已完成同器件布线且通过相同功能校验的原生和候选 RTL，先要求建立和保持裕量都非负，再按固定频率周期选择；两者均不达标就将该程序记为暂时无法部署。在上述七个程序上，它为五项返回合格网表，FDTD-2D 和 Cholesky 被如实记为未达标。这个后处理避免用“周期 × 10 ns”报告不可达到的时间，仍需另行优化未通过的路径。[可执行的时序验收](paper_timing_admission.py) · [7 项验收结果](paper_timing_admission_20261125.json)

最终 27/27 修复版的多循环部署沿用这七例逐项核对。GEMM、BiCG、SYR2K 共三份网表逐字节相同，沿用已布线的实测结果；其余四份 RTL 全部重新仿真、布局布线。FDTD-2D 的多循环版比单循环版少 10,400 拍，建立裕量却从 −4.429 ns 变为 −6.121 ns，估算执行时间从 1,910.11 µs 增至 1,966.44 µs。这是同一工具内“周期减少、实现变慢”的直接反例。最终 Cholesky 用 281,304 拍，仍少于 Bambu 的 317,584 拍，但估算时间为 3,448.79 对 3,000.53 µs，且前者未达 100 MHz。七例中手写与 Agent 有六份网表哈希相同，包括唯一比 Bambu 更快的 GEMM。[最终 7 项逐例数据与实现细节](paper_physical_final_20261125.md)

## 对论文主张的判断

“每个 benchmark 都严格超过所有论文结果”无法作为这批实验的统一停止条件。在 HeuriGym 的 23 个已证最优实例上，最小完成周期已经没有下降空间；仍可比较求解时间。Light-HLS 与 Bambu 有可对齐的完整程序，实测仍有明显差距；其中有些需要支持变迭代次数的流水或缩短硬件组合路径。HEART 的动态相位优化、RKHS、NeuroSchedule2.0 的精确输入或配置尚缺，其他若干论文的主要指标是面积、持续吞吐或板上执行时间。把这些情况合并成一个“胜率”会掩盖真正的技术问题。[逐篇工件、指标与缺项](paper_baselines_20261125.md)

现阶段论文可支持的结论是：真实后端为 Agent 揭示了图模型省略的约束；扩大循环调度的选择范围能缩短完整程序周期；强人工控制和物理实现又能检出模型选择中的不足。值得作为后续独立检验的假设，是让模型根据编译器的循环可行性、动态执行频率和关键路径诊断共同分配有限的探测预算，在全新程序家族上提高**通过目标时钟的硬件**的性能。当前这批案例今后属于已经观察的数据。

这次“14 篇”沿用收集快照的论文范围。之前讨论过的 AlphaEvolve-XLS 在项目记录中属于相关公开工程，尚未核实相应正式论文，本轮并未直接评测它生成的 XLS 调度器。XLS 组内的 SDC/ASAP 数字仅对应表中列出的两种实现。[Agent 算法发现相关工作](../../docs/research/02_agent_algorithm_discovery.md)
