# 最终部署 RTL 的完整输出数组校验

2026-11-25。27 个 Vericert 程序的 Agent 和手工策略各覆盖 31 个最终输出数组、22,502 个 32 位元素。Icarus 四态仿真均在原先记录的完成拍结束。所有元素与原生 C 一致，未出现未知位。两种策略在 23 个程序部署了相同的 RTL，因此本次独立运行了 31 份不同的 RTL。[逐程序数组摘要、RTL 哈希和结果](paper_final_arrays_20261125.json)

从作者主函数的最终 `print_array` 或 `check_array` 调用识别输出对象，保留其所有维度。`bicg` 和 `mvt` 各有两个输出，`fdtd_2d` 有三个。C 观测只增加了返回前的字节复制，分别用 Clang `-O0` 和 `-O1` 编译，两者产生的完整数组逐项一致。验证脚本从已冻结的单循环或多循环部署记录解析实际 RTL 文件，并检查结果集来源哈希、配置选择和实际完成周期。在 `ap_done` 有效后用只读层次探针访问完整输出 RAM，再逐项比较。[验证脚本](paper_final_arrays.py)

## 四个全零胜例的非零输入压力验证

在四份原始部署 RTL 上分别执行三组额外输入。硬件描述、运算核心、标量和数组尺寸保持与主实验一致。testbench 先运行作者的初始化，检查输入 RAM 的每一个元素均为原定的零，然后在首次到达计算核心入口状态的下降沿向输入 RAM 写入新值。写入只发生一次。C 参考运行执行相同的初始化和输入替换，直接调用原计算函数，以 Clang `-O1` 和 UBSan 检查运行。每个程序使用种子 20261125、20261126、20261127，输入元素独立均匀取自整数 `[-3, 3]`。[压力验证脚本](paper_final_arrays_stress.py)

| 程序 | 注入数组 | 注入拍 | 每组输出规模 | 三次运行的非零元素数 | 三次运行的不同输出值数 | FSM 路径 |
|---|---|---:|---:|---|---|---|
| `gemm` | A、B、C | 34,180 | 500 | 494 / 495 / 487 | 103 / 100 / 98 | 全部与原输入逐拍一致 |
| `2mm` | A、B、C、D | 28,816 | 384 | 383 / 384 / 384 | 285 / 274 / 303 | 全部与原输入逐拍一致 |
| `3mm` | A、B、C、D | 30,824 | 352 | 352 / 352 / 351 | 337 / 340 / 346 | 全部与原输入逐拍一致 |
| `doitgen` | A、C4 | 14,520 | 960 | 941 / 935 / 931 | 76 / 79 / 82 | 全部与原输入逐拍一致 |

12 次四态仿真覆盖 6,588 个输出元素，全部逐字等于 C，每轮的返回校验值也一致。每次从接受启动到完成的完整 FSM 状态序列都与同一网表在原输入下的序列逐字节相等。数据因此覆盖了非零运算和累加，但没有增加新的控制流路径。对论文的 8 个周期胜例仍只使用作者原输入。原始网表、输入、输出和状态轨迹的哈希均已保存。[逐次压力验证结果](paper_final_arrays_stress_20261125.json)
